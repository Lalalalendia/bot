# BOR v0.1 — тестовое внедрение (не production)

Кандидат: `feat/bor-antibot-v01` ([PR #2](https://github.com/Lalalalendia/bot/pull/2)).
Цель: проверить защиту Telegram при вступлении в **отдельной тестовой супергруппе**.
Не переводить рабочего бота на этот код до реальной приёмки.

## Перед запуском

1. Подготовить **отдельного тестового Telegram-бота** и отдельную тестовую супергруппу.
2. Включить у тестового бота администратора: `can_restrict_members`, `can_delete_messages`, `can_invite_users`. Убедиться, что обычные участники группы могут писать после прохождения проверки.
3. Убедиться, что для данного токена не работает второй `getUpdates`-poller и не настроен webhook.
4. Создать локальный `.env` на машине с Docker:

   ```ini
   BOT_TOKEN=YOUR_PRIVATE_TEST_BOT_TOKEN
   TEST_CHAT_ID=-1000000000000
   RUST_LOG=info
   ```

   Не отправлять токен или `.env` в чаты, GitHub или Notion.

5. Зафиксировать тестируемый commit SHA командой `git rev-parse HEAD`. Работать с веткой PR #2, а не с `main`.

## Пошаговый старт и остановка

```bash
docker compose build
docker compose run --rm rebuild --preflight
# Продолжать только если получен Telegram preflight PASS
docker compose up -d --no-build
docker compose ps
docker compose logs --tail=100 rebuild
```

Контрольные сценарии: [Notion BOT-R2-ACCEPT-01](https://app.notion.com/p/40032a84beec81d4af2ad2750ff08801).

- [ ] Вступивший до CAPTCHA не может отправлять текст и медиа.
- [ ] Единственный неправильный ответ приводит к одному исключению.
- [ ] Правильный ответ снимает запрет; собственное сообщение в пределах 10 минут завершает проверку.
- [ ] Правильный ответ без сообщения: исключение по истечении 10 минут.
- [ ] Нет ответа на CAPTCHA в течение 120 секунд: исключение.
- [ ] После перезапуска не происходит повторных санкций над уже подтверждённым пользователем.

Для каждого теста зафиксировать ожидаемый/фактический результат, PASS/FAIL и SHA без личных данных.

Остановить пилот без удаления базы:

```bash
docker compose down
```

Не запускать `docker compose down -v`: это удалит именованный том `rebuild_data` и данные SQLite.

## Границы

- `--preflight` **не проверяет** реальное прохождение CAPTCHA; это только проверка токена, прав и конфигурации.
- Telegram отправляет уведомление о прямом вступлении уже после события — нулевое окно отправки гарантировать нельзя. Режим предварительных заявок обеспечивает проверку до входа.
- Тесты с локальным Telegram mock и зелёный CI не доказывают реальную доставку сообщений.
- В первой версии одна CAPTCHA, одна попытка и 10 минут на первое сообщение. Межботовая память и дополнительные режимы вне scope.
- При любом FAIL остановить тестовый контейнер, оставить PR черновиком и исправить проблему перед следующей попыткой.
