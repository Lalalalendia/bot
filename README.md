# Бот Ребилд

Telegram-бот для нашего книжного сообщества. Основная реализация пишется на **Rust**. Существующий Python-проект Shield24 v0.1.0 сохранён в Notion как эталон поведения, а не как рабочий код этого репозитория.

**Статус:** первая Rust-версия в [Draft PR #1](https://github.com/Lalalalendia/bot/pull/1). Работа в живом Telegram и пригодность для защиты действующего чата пока **не подтверждены**.

## Что реализуется в v0.1

- Проверка входящих участников математической CAPTCHA с ограничением возможности писать до успешного ответа.
- Обычные заявки на вступление с отправкой проверки через Telegram `user_chat_id`, когда этот идентификатор доступен.
- Обработка повторных событий, устаревших уведомлений и чужих ответов на CAPTCHA.
- Таймер, ограничение попыток, отклонение заявки или временное исключение.
- Настройки каждой группы: /guard, /timeout, /attempts, /links, /lockdown.
- /pending, /allow ID, /deny ID и /stats для ручного разбора и восстановления.
- SQLite WAL, журнал действий, сохранение offset обновлений, эксклюзивная блокировка базы для единственного процесса.
- Отдельное состояние `manual` для непроверенных результатов Telegram API; действия не считаются успешными до ответа Telegram.

База сохраняется между перезапусками. Модератор должен разбирать записи со статусом `manual`: бот намеренно не повторяет неопределённые внешние действия без проверки.

## Запуск на компьютере

Требуется стабильный Rust toolchain и токен бота, полученный через [@BotFather](https://t.me/BotFather). Токен **нельзя** публиковать в GitHub, Notion или переписке.

Linux:

```bash
export BOT_TOKEN="***"
export DATABASE_PATH="./data/rebuild.sqlite3"
cargo run --release
```

Windows PowerShell:

```powershell
$env:BOT_TOKEN = "***"
$env:DATABASE_PATH = ".\\data\\rebuild.sqlite3"
cargo run --release
```

Один экземпляр бота использует одну SQLite-базу. Второй процесс с тем же `DATABASE_PATH` должен получить ошибку блокировки. Не запускайте несколько опрашивающих процессов с одинаковым BotFather-токеном.

## Docker Compose

Создайте локальный файл `.env` из `.env.example` и заполните токен. Этот файл исключён из Git.

```bash
docker compose up -d --build
docker compose logs -f rebuild
```

Данные помещаются в именованный том `rebuild_data`. Контейнер выполняется под непривилегированным пользователем.

## Проверки

```bash
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
cargo build --release --locked
docker build --tag rebuild-bot:local .
```

CI проверяет **зафиксированное в Git форматирование** (без автоматического исправления) и использует **зафиксированный `Cargo.lock`**. Отдельные обязательные проверки собирают release-бинарник и Linux Docker-образ. Исходники новой реализации не считаются прошедшими приёмку, пока все задания не завершатся успешно на одном HEAD.

В тестах используются изолированная SQLite и локальный имитатор Telegram HTTP API. Они **не заменяют** испытания на реальной тестовой супергруппе.

## Административные ограничения

Боту нужны права Telegram на ограничение участников и обработку заявок, а при включённом фильтре ссылок — удаление сообщений. Настройки фильтра ссылок по умолчанию выключены.

Текущая версия не восстанавливает индивидуально заданные права участников в точности, не реализует Guardian Bot API, не имеет книжных модулей или полноценной системы жалоб. Заявленные в Notion **72 функции — очередь кандидатов**, не список реализованных возможностей.

Подробные ограничения: [RUST.md](RUST.md).
